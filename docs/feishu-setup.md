# 配置飞书机器人通知

配置后，AI 通过 feedback 请求你时，会把**摘要推送到飞书**；你在飞书里**直接回复**，反馈就会同步回 Cursor。适合你离开电脑、想用手机回复的场景。

> 配不配飞书都能在侧边栏正常收发反馈，配了就多一条「手机上回复」的通道，还能用 `/new` 从手机拉起 CLI 会话。

---

## 你属于哪种情况？

- **公司 / 团队在用飞书**（最常见）：按下面步骤创建一个「企业自建应用」即可。
- **只有个人飞书账号**：一样可以。飞书允许你创建一个「测试企业」来建应用，自用免审核。
- **还没有飞书**：先到 [feishu.cn](https://www.feishu.cn/) 免费注册，再回到这里。

最终你只需要拿到两样东西，填进插件即可：

- **App ID**（形如 `cli_xxxxxxxx`）
- **App Secret**（一串密钥）

---

## 操作步骤

### 第 1 步：创建应用

1. 打开飞书开放平台：<https://open.feishu.cn/app>
2. 点「创建企业自建应用」，填名称（例如 `Cursor 反馈`）和图标，创建。
   - 如果你没有企业 / 是个人用户：飞书会引导你创建或加入一个企业，可以创建「**测试企业**」用于自用，免审核。

### 第 2 步：开启机器人能力

1. 进入应用 → 左侧「添加应用能力」→ 找到「**机器人**」→ 启用。

> ⚠️ 必须**先启用机器人**，否则第 3 步的消息权限无法申请。

### 第 3 步：申请权限

在左侧「权限管理」里搜索并添加这些权限：

- `im:message` —— **必须开启**。它同时覆盖：① 机器人给你发消息（推送反馈卡片）；② 下载你发来的图片 / 文件 / 语音等资源。
- `im:message.p2p_msg:readonly` —— 让机器人能读取你和它单聊的消息（用于接收你的文字回复）。

> ⚠️ 不要只开 `im:message:send_as_bot`。它只能「以机器人身份发消息」，**无法下载你发来的图片 / 文件**——那样你发图片给机器人会收到「图片接收失败：缺少 im:message 权限」。
>
> 自用无需开启「允许被添加到外部群」「允许外部用户单聊」。

### 第 4 步：填入凭证，让机器人先连上

1. 在「凭证与基础信息」页，复制 **App ID** 和 **App Secret**。
2. 回到 Cursor，点反馈面板顶部的「通知设置」图标，打开配置弹窗。
3. 粘贴 **App ID** / **App Secret**，输入框失焦即自动保存（无需点按钮）。

> 填好后，插件会用这对凭证和飞书建立一条**长连接**。下一步在飞书后台保存「长连接」方式时，要求这条连接此刻在线，所以先做这步。

### 第 5 步：配置事件订阅

机器人通过**长连接**接收你的消息，本地运行即可、无需公网地址。在飞书后台：

1. 左侧「**事件与回调**」→「**事件配置**」。
2. **订阅方式**选「**使用长连接接收事件**」并保存。
   - 保存会校验长连接在线；若失败，回第 4 步确认凭证已填、重载 Cursor 窗口让机器人重连。
3. 点「**添加事件**」，添加「**接收消息 `im.message.receive_v1`**」。

### 第 6 步：发布版本

1. 左侧「版本管理与发布」→ 创建版本 → 填版本号和说明 → 申请发布。
2. 第 3 步的权限、第 5 步的事件订阅，**都要发布后才真正生效**。
3. **测试企业 / 自建应用**通常自动通过或免审；正式企业版可能需要管理员审批通过后才生效。

### 第 7 步：绑定接收方（关键一步）

发布生效后，**在飞书里给你的机器人发任意一句话**（比如「hi」）。

- 机器人收到后，会把「你」记为接收方，之后所有反馈卡片都会推给你。
- 插件弹窗里的状态点变**绿色** = 绑定成功。

## 在 mcp.json 里配置飞书

通常直接在插件面板里填凭证即可（上面第 4 步）。如果想把配置固化在 `mcp.json` 里（比如团队统一分发），也可以走 `env`：

```json
{
  "mcpServers": {
    "cursor-feedback": {
      "command": "npx",
      "args": ["-y", "cursor-feedback@latest"],
      "env": {
        "FEISHU_APP_ID": "cli_xxxxxxxx",
        "FEISHU_APP_SECRET": "your_app_secret"
      }
    }
  }
}
```

| 环境变量 | 默认值 | 说明 |
|---------|--------|------|
| `FEISHU_APP_ID` | - | App ID（形如 `cli_xxxxxxxx`） |
| `FEISHU_APP_SECRET` | - | App Secret |
| `FEISHU_ENABLED` | `true` | 是否推送反馈到飞书，设 `false` 关闭 |
| `FEISHU_ACK` | `true` | 收到你的回复后是否回「Get」表情回执，设 `false` 关闭 |

- 优先级：**插件面板（填了凭证）> mcp.json env > 默认**。两边都配时以面板为准。
- 不管用哪种方式，飞书后台的权限、事件订阅、发布（第 2–6 步）都要先配好，最后第 7 步「发消息绑定」也要做一次。

## 常见问题

- **状态一直是黄色「请发消息绑定」**
  去飞书主动给机器人发一条消息；同时确认应用已发布、机器人能力已开启、**事件订阅已配好**（第 5 步，没配的话机器人收不到你的消息，自然绑不上）。

- **收不到卡片**
  检查 App Secret 是否填错（可重新填写，失焦自动保存）；确认 `im:message` 权限已通过。

- **在飞书回复了，但没同步回 Cursor**
  按顺序排查：① 「事件与回调 → 事件配置」里订阅方式是「使用长连接接收事件」，且已添加「接收消息 `im.message.receive_v1`」事件；② 已开启 `im:message.p2p_msg:readonly` 权限；③ 改完这两项后**重新发布过版本**。多窗口时请「**回复**」对应的那张卡片，而不是直接发新消息。

- **发图片 / 文件给机器人「没反应」或提示「图片接收失败」**
  下载资源需要 `im:message` 权限（注意不是 `im:message:send_as_bot`）。开启后**重新发布版本**，再到 Cursor 里重载窗口让机器人重连即可。

- **多个项目 / 多个窗口同时在等反馈**
  如果你直接发消息而不是回复某张卡片，机器人会列出待处理的请求并反问你回复哪一条。最稳妥的做法是在卡片上点「回复」（桌面端右键、手机端长按），这样能精确对应。

- **安全提醒**
  App Secret 等同于密码，只保存在你本机，不要外泄。怀疑泄露时，在开放平台「重置」密钥后，回插件重新填写即可。
